ユーザーが自分の手で改稿した原稿と AI 初稿を比較し、**変更のパターンからユーザーの文体規則を抽出**して canon に登録する。実使用で最も効果が高かった手法であり、抽出した規則は以降の writer 出力を直接改善する。

# 手順

## 1. 比較対象の特定

- $ARGUMENTS が章番号なら: AI稿 = `state/reference/chNN-ai-draft.md`(canon-sync が自動退避したもの)、改稿版 = 現在の `manuscript/chNN.md`
- パスが2つ渡されたらそれを使う(1つ目 = AI稿、2つ目 = 改稿版)
- AI稿の退避が無い場合はユーザーに所在を聞く。**改稿版を AI稿と取り違えないこと**(diff の方向が逆になると規則が全部逆になる)

## 2. 差分の分析

両方を読み、変更点を全て列挙して分類する:
- **削除**: ユーザーが消した表現(最重要。AI の癖はここに出る)
- **言い換え**: 同じ内容の別表現化(方向性を読む: 直接→間接、硬→軟、説明→動作 など)
- **追加**: ユーザーが足したもの(AI に欠けている要素)
- **構造変更**: 場面・段落・台詞の再配置

## 3. 規則の抽出

分類した変更からパターンを抽出する。規律:
- **1つの変更から規則を作らない。** 同型の変更が3例以上あるものだけ規則化する(単発は個別修正であって好みの規則ではない)
- 各規則に**逆方向の反例がないか**を必ず確認する(例: 「意味の言い直しを削除」規則を立てる前に、「平易な因果説明は残されている」ことを確認 → 規則は「意味づけは不可、因果説明は可」と精密化される)
- 規則は必ず**実例つき**にする: `AI稿「…」→ 改稿後「…」`
- 抽出済みの規則(style.yaml の writing_rules)と照合し、既存規則の精密化なのか新規則なのかを区別する

参考: 実使用で抽出された規則の例 — 「地の文で出来事の意味を言い直さない(因果説明は可)」「対句・反復・倒置の禁止」「台詞は口語的で多少冗長でよい」「噂話はぼかさず具体的に」「った。連鎖を崩す」「感覚描写は具体物で置く」

## 4. 提案と登録

1. 抽出した規則の一覧(実例つき)+ 定量化できるもの(読点上限・文末連続など)は `quantitative` への追加案としてユーザーに提示する
2. **ユーザーが承認した規則だけ**を登録する:
   - 文体全般 → `canon/style.yaml` の `writing_rules`(実例コメント付きで)
   - 特定キャラの台詞に関する規則 → そのキャラの `speech.never` / `speech.tone`
   - 機械検出可能なもの → `style.yaml` の `quantitative`
3. 登録後、次回以降の writer はこれを最優先ルールとして読む(コンテキストパックの style セクションに載る)

# 注意

- 誤字修正・単純な事実修正は文体規則ではない。除外する
- ユーザーの改稿にも揺れがある。矛盾する変更を見つけたら、規則化せずユーザーに確認する
- このコマンドは原稿を変更しない(canon への登録のみ)
