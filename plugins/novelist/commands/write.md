---

第 $ARGUMENTS 章の執筆パイプラインをオーケストレーションする。あなた(メインエージェント)は執筆せず、進行役に徹する。

# パイプライン

## 1. コンテキストパック生成
```
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/build_context_pack.py" <章番号> --project <プロジェクトルート>
```
- outline に章が無い/キャラ id 未登録の警告が出たら、**執筆に進まず**ユーザーに確認するか `/novelist:outline` を案内する。
- `state/character-state.yaml` の `as_of_chapter` が「前章の番号」より小さい場合は canon-sync 忘れ。先に `/novelist:canon-sync` を実行するようユーザーに提案する。

## 2. 執筆 — writer エージェントを起動
Agent tool で `novelist:writer` を起動(run_in_background: false)。プロンプトに渡すもの:
- コンテキストパックのパス / 原稿の出力先(config の manuscript_pattern に従う)
- 章番号と、ユーザーからの追加指示($ARGUMENTS の2つ目以降)
保存時に hook の自動 lint が走り、機械検出できる矛盾は writer がその場で直す。

## 3. 独立検証 — writer の自己申告を信用しない
writer 完了後、メインエージェントが自分で実行して確認する(writer の報告は古い情報を引き写すことがある):
```
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/lint_manuscript.py" <原稿> --project <ルート>
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/count_chars.py" <章番号> --project <ルート>
```
- lint が [CANON] エラーを出したら、それは原稿ではなく canon の問題。**メインエージェントが canon を修復**してから続行する(writer に canon の編集権限はない)
- 文字数が目標から大きく外れていたら(±20%目安)、監査結果と併せて改稿指示に含める。**文字数の報告には必ず count_chars の実測値を使う**(writer の自己申告は過大になる)

## 4. 監査 — 4エージェントを並列起動
**1つのメッセージで4つ同時に** Agent tool を呼ぶ:
- `novelist:continuity-auditor` — 章番号・原稿パスのみ渡す(**writer の意図や報告は渡さない**。本文と canon だけで判断させる)
- `novelist:style-auditor` — 章番号・原稿パス
- `novelist:foreshadow-keeper` — 章番号・原稿パス
- `novelist:plausibility-auditor` — 章番号・原稿パス(場面の因果・感情の温度・台詞の自然さ。他3体の死角を担当)

## 5. 差し戻し判定
監査報告を集約し、重複を除いたうえで**3分類**する:
1. **要修正**: canon との矛盾・規範違反など機械的に正しい指摘 → writer に差し戻して改稿
2. **意図確認**: 意図的なら維持してよい指摘(呼称の揺れ・リーダーの演出など) → writer に「意図的か」を問い、理由付きの回答なら維持を認める
3. **要確認(説得力監査の指摘は原則全部ここ)**: 主観的判断を含むもの → **自動差し戻しせず**、ユーザーへの報告に回す

差し戻しの運用:
- writer への差し戻しは分類付きで渡し、**改稿後の再監査は変更範囲に絞る**(全文再監査はトークンの無駄。「変更した場面のみ」「canon 側の既知のズレは指摘から除外」と明示して再実行する)
- このループは最大2周。2周して解消しない指摘は「未解決」としてユーザーに委ねる
- 監査が「canon への疑義」を挙げた場合は、原稿の問題と区別してユーザーに報告する(canon の修正は人間の判断)

## 6. ユーザーへの報告
以下をまとめて提示する:
- 章のあらすじと文字数(**count_chars の実測値**)、原稿パス
- 監査結果の要約(解消済み / 未解決 / **要確認** — 説得力監査の指摘はユーザーが判断する)
- writer の **確定事実リスト** と **【新規】固有名詞リスト**
- 次のアクション: 内容を確認して問題なければ `/novelist:canon-sync <章番号>` を実行するよう案内(**canon-sync するまで、この章の新事実は canon に反映されず、次章で矛盾の種になる**ことを明記する)
- ユーザーが原稿を自分の手で改稿した場合は、`/novelist:learn-style <章番号>` で文体規則を抽出できることを案内する

# 注意

- 手順を省略しない。特に監査3体の並列起動と、指摘があるときの差し戻しは必須。
- あなた自身が原稿を直接書き換えない(修正は必ず writer 経由。監査の独立性を保つため)。
