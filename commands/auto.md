全自動執筆モード。ユーザーの関与は「最初の要件」と「案の選択」の2回だけ。以降は納品まで自動で進める。品質保証の仕組み(パック生成・自動lint・監査3体・canon-sync)は手動モードと同一で、**一切省略しない**。省略するのはユーザーへの都度確認だけである。

# 再開判定(最初に必ず)

プロジェクトの状態を見て、途中からの再開に対応する:
- `canon/world.yaml` の title が空 → 手順1から
- canon はあるが `plot/outline.yaml` が空 → 手順4から
- outline まであり原稿が途中 → 手順5の「次の未執筆章」から再開(`state/character-state.yaml` の as_of_chapter と原稿を突き合わせ、sync 漏れがあれば先に canon-sync)
- 全章執筆済み → 手順6(納品)だけ行う

# 手順

## 1. 要件ヒアリング(1回だけ)

$ARGUMENTS から読み取れるものは聞き直さない。不足分だけを AskUserQuestion で**1回にまとめて**聞く:
- 目標文字数(→ 章数を自動算出: 1章 3,000〜5,000字目安)
- ジャンルの希望(「お任せ」可)
- 読後感(ハッピー/ビター/考えさせる 等)・NG要素(残酷描写NG等)
これ以上は聞かない。決まっていないことは案の中で提案して選ばせる。

## 2. 作品案を10案提示

要件の範囲内で、**方向性が互いに重ならない**10案を番号付きリストで提示する。各案は4行以内:
```
1. 『タイトル案』(ジャンル)
   ログライン(主人公・目的・障害を1文で)/ フック(この話ならではの仕掛け)/ 結末の方向
```
お任せ要素が多いほど振れ幅を大きく(時代・トーン・視点・スケールを散らす)。
提示したら「番号で選んでください(組み合わせ・修正注文も可)」と伝えて**ターンを終える**。

## 3. 自動設定構築(interview の全自動版)

選ばれた案をもとに、ユーザーに質問せず canon を自分で埋める。`/novelist:init` 未実行なら先に実行。書く順番と要点:
1. `canon/world.yaml` — 世界観・絶対ルール・**banned_words**(時代設定から機械的に導く。中世なら現代語一式)
2. `canon/style.yaml` — 人称・視点ルール・トーン(案の読後感から決める)
3. `canon/characters/*.yaml` — 主要キャラ(短編3〜4人、長編5〜8人)。各キャラ **summary 1行・speech(台詞例2つ以上)・invariants** を必ず埋め、事故りやすい属性は `lint.forbid` も書く
4. `canon/glossary.yaml` — ここまでの固有名詞を全登録(誤表記しやすい variants も自分で考えて登録)
5. `canon/constraints.yaml` — **スキップ禁止。** 各キャラの能力・世界のルールごとに「これがあると成立しない展開」を否定形で最低3件は洗い出す
6. `state/knowledge.yaml` — 物語の核となる秘密を登録し、known_by を絞る

## 4. 自動章立て(outline の全自動版)

- 目標文字数から章数を決め、三幕構成で `plot/outline.yaml` を書く(各章: pov / characters / locations / summary / 伏線)
- `plot/foreshadowing.yaml` — 核となる謎・どんでん返しを伏線化。**全項目に payoff と due_by 必須**、全伏線がどこかの章で回収される計画にする
- 自己検証: characters の id 実在 / 伏線の回収漏れ / constraints と矛盾する展開が無いか。問題があれば自分で直す
- ここで一度ユーザーに「設定と章立ての要約」を1画面程度で報告し、**確認は求めず**そのまま執筆に進む(方向転換したければユーザーが割り込める)

## 5. 全章自動執筆ループ

第1章から最終章まで、章ごとに `/novelist:write` と同じパイプラインを回す:
```
パック生成 → writer 執筆(自動lint) → 監査3体並列 → 差し戻し改稿(最大2周) → canon-updater で sync
```
- 章ごとの報告は進捗1行のみ(「第3章 完(4,200字)/ 監査指摘2件解消」)。詳細は最後にまとめる
- 監査の「要人間判断」や2周で解消しない指摘は、**止まらずに**自分で最も安全な解決(canon 側を正とする)を選んで進み、納品報告に判断記録として残す
- プロジェクトが git 管理下なら、章の sync 完了ごとにコミットする(チェックポイント。メッセージ例: `ch03: 執筆+canon-sync`)
- 文字数が目標を大きく外れそうなら outline を自分で調整(章の追加・統合)してよい。伏線の due_by は必ず守る

## 6. 納品

1. 最終チェック: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/lint_manuscript.py" <全原稿> --project <ルート>` と、全章一括の整合性監査(continuity-auditor に通し読みさせ、章間矛盾を最終確認)。指摘があれば修正してから納品
2. 結合: `python3 "${CLAUDE_PLUGIN_ROOT}/scripts/compile_manuscript.py" --project <ルート>` → `build/<タイトル>.md`
3. 納品報告:
   - 作品タイトル・総文字数・章数・あらすじ
   - 納品ファイルのパス(git 管理下なら最終コミットも)
   - 伏線の仕込み/回収の一覧(全て回収済みであること)
   - 執筆中に自動判断した事項の記録(要人間判断を代行した箇所)
   - 未解決の監査指摘(あれば正直に)

# 禁止事項

- 品質パイプラインの省略(監査を飛ばす・canon-sync を飛ばす・lint 指摘の放置)
- 手順2と4の報告以外でユーザーに確認を求めて止まること
- 目標文字数の大幅未達のまま「完了」と報告すること
